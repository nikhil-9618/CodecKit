What is k-anonymity?

“Is my password in a breach database?” is a question a service can answer, but the obvious implementation is terrible: send the password, get a yes or no. Now the service knows your password. Hashing it first does not help much either — send SHA-1(password) and the server can still test that exact hash against millions of candidates, and a leaked hash is a password-cracking target forever.

k-anonymity, as applied by Have I Been Pwned's Pwned Passwords API, inverts the trust: the client asks about a group of passwords instead of one, and does the final matching locally.

The protocol

  1. Hash the password locally with SHA-1. This produces 40 hex characters.
  2. Send only the first 5 characters to api.pwnedpasswords.com/range/<prefix>.
  3. The server returns every suffix in its dataset that shares that prefix — typically several hundred to a few thousand lines of SUFFIX:count.
  4. The client compares the remaining 35 characters itself. A match means the password is in the corpus, and the count says how often it appeared.

The server never sees the full hash. It cannot tell which of the returned suffixes the client cared about, because the client downloads all of them. The request reveals only that someone, somewhere, holds a password whose hash starts with those five characters.

Why five characters

Five hex characters encode 20 bits, so there are about 1,048,576 possible prefixes. With roughly 109 breached passwords in the corpus, each prefix covers on average a thousand entries — the k in k-anonymity. Large enough that the request does not identify an individual password; small enough that the response stays under a few hundred kilobytes. Sending four characters would return tens of thousands of lines; sending six would narrow the anonymity set too far.

Note the honest limitation: the prefix is a partial fingerprint. If an attacker already suspects a specific password, they can check whether its prefix matches a request they observed. k-anonymity hides you among k candidates — it is not zero knowledge.

What the client must still do

The comparison must be constant-time-ish and, more importantly, local. A service that sends the remaining 35 characters “to speed things up” has thrown the property away. The same applies to logging: if the browser extension, proxy or analytics layer records request URLs, it records the prefix. CodecKit makes exactly one request per check, to one host, and sends nothing else.

k-anonymity beyond passwords

The general idea predates breach checks. A dataset is k-anonymous if every record is indistinguishable from at least k−1 others on the quasi-identifiers people might use to re-identify it — postcode, birth date, gender. Hospitals and census bureaus generalise or suppress fields until each combination covers at least k people. The password API is the same idea at query time: bucket the data coarsely, then resolve locally.

Related constructions go further. Private set intersection lets a client learn whether an item is in a server's set without revealing the item or the set; homomorphic encryption lets the server compute on ciphertext. They are more expensive and rarely necessary for a breach check, but they solve the same shape of problem.

What it does not fix

  • A breach hit does not mean the password is currently exposed at your site — it means it is in a public corpus and should never be allowed.
  • A miss does not mean the password is strong. It means this corpus has not seen it.
  • The check says nothing about reuse across sites, which is the actual root cause of most account takeovers.

Use it as one input to a policy, alongside length, a blocklist of common patterns and rate limiting. Reject known-breached passwords at signup; that single rule removes most credential-stuffing success.

See it in action

The password strength tool implements this exact flow: SHA-1 in the browser, a five-character request, local matching. Open the network panel and you will see the range URL and nothing else. Everything else on the page — entropy, classes, crack-time estimate — is local arithmetic.
