How hexadecimal represents text

Every byte is two hexadecimal digits, so a string is just its UTF-8 bytes written in base 16. Hello is five bytes — 48 65 6c 6c 6f — because ASCII letters fit in one byte. Characters outside ASCII take more bytes: é is c3 a9, the euro sign is e2 82 ac, and an emoji needs four. The decoder here strips spaces, colons and 0x prefixes, rebuilds the byte array, then asks the browser's UTF-8 decoder for the text.

That last step matters. Decoding byte-by-byte as Latin-1 would turn every multi-byte character into mojibake. If the bytes are not valid UTF-8 — for example an encrypted blob or a PNG header — the result will be replaced characters rather than a crash.

Where hex dumps come from

  • xxd, hexdump -C and od -A x -t x1z on Linux and macOS.
  • Packet captures: Wireshark's “Copy → as Hex Dump”.
  • Hash digests, which are simply fixed-length hex strings such as SHA-256's 64 characters.
  • Binary protocol fields, MAC addresses and bytecode listings.

Debugging tips

If a value refuses to decode, count the digits. An odd count means a nibble is missing. If the count is even but the output looks wrong, the payload may be compressed, encrypted or encoded in a legacy single-byte charset rather than UTF-8. When you are looking at a hash instead of a message, the hash identifier can tell you which algorithm produced it from its length and alphabet.

Hex is also the natural companion of the Base64 decoder: base64 hides the bytes in a different alphabet, but after decoding you can inspect them as hex.

Frequently asked questions

Does it accept spaces and 0x prefixes?

Yes. Whitespace, commas, colons and 0x are ignored.

Why did my hex string fail?

The digit count is odd, or a character is not a hex digit.

Is the text sent anywhere?

No. Conversion runs locally and the page works offline.
